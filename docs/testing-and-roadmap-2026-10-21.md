# 300036 真机测试与后续完善建议

## 版本范围

当前已提供的 Android/iOS 包为 `2.11.1+300036`，应用源码对应 `201962ff`。
`b55c9c9f` 只修复 Web 测试资源路径，应用源码相同。

本次 Release 的更新弹窗、仓库链接和构建号显示改动尚未打包，**不能在 300036 中验证**。
现在看到旧更新弹窗属于已确认遗漏，不需要卸载重装或清除数据。

## 建议先测这几项

尽量使用测试聊天和第二个账号。记录设备、系统版本、对方客户端、操作步骤和大概时间。
不要为验证恢复功能主动删除数据库、退出唯一账号或破坏密钥。

| 项目 | 操作 | 预期 | 本批差异 |
| --- | --- | --- | --- |
| 旧账号升级 | 保留当前账号，关闭并重新打开；开飞行模式再启动，恢复联网 | 账号保留，恢复联网后能收发；旧加密聊天仍可读 | SDK 安全存储接入、失败不轻易删库 |
| iOS 粘贴图片 | 在照片或截图预览中复制图片；聊天输入框长按，选择粘贴图片 | 先出现图片预览，可取消；确认后正常发送，方向正确 | 新增输入菜单图片入口 |
| 房间邀请 | 第二账号邀请测试账号；点邀请，分别试接受、拒绝；另建邀请试拒绝并屏蔽 | 打开邀请不会自动加入；操作结果符合选择 | 改为明确确认流程 |
| 空间邀请 | 邀请加入一个测试空间，接受后查看列表 | 切到该空间，能看到对应房间 | 补齐空间接受后的导航 |
| 语音互通 | 分别录 3 秒、30 秒语音；向 Element/Element X 等客户端发送，再反向发送 | 双向可播，长度正常，拖动和重播无异常 | 优先 Opus、能力不足时 AAC 回退；原转换兼容保留 |
| 语音转文字 | 同一条清楚的中文语音试转文字；再试对方发来的语音 | 正常返回文字；失败有提示 | 调用与限额规则未新增改动，主要做回归 |
| 图片和相机 | 拍横向、竖向照片；取消一次，再发送一次；复制图片再发 | 方向、预览、取消和发送正常 | 原生相机保留，验证升级未回归 |
| 通话 | 两人通话，切扬声器/蓝牙；锁屏后返回；有条件再试三人加入与退出 | 声音路由正确，成员变化正常，无串房间状态 | RTC 服务发现、密钥过滤、成员刷新 |
| 深链 | 从浏览器打开真实 `matrix:` 房间/事件链接；多账号时试指定账号链接 | 正确选择账号和房间；有权限时定位事件 | 更完整解析事件、via 和多账号信息 |
| 恢复密钥复制 | 在已有安全备份流程里点“复制” | 仅复制，不弹系统分享 | 修复复制动作 |

语音“不支持 Opus 时回退”取决于设备能力，普通录音正常不能证明回退分支已覆盖。
历史消息若原本缺少密钥，本批不会凭空恢复其解密能力。

## Android 额外验证

1. 在通知设置选择“永久通知”，确认后台服务常驻通知出现。
2. 分别在应用打开、退到后台、冷启动时由第二账号发消息，点击通知。
3. 多账号时给不同账号发消息，确认点击后进入正确账号和房间。
4. 观察锁屏约 10 分钟后是否仍能收到；如果失败，记录电池限制、自启动和厂商系统设置。

Android 系统设置中的“强行停止”会阻止应用继续运行，不能将此场景当作常驻同步应保证工作的前提。

## iOS 通知的边界

旧 ntfy 页面和注册逻辑已经移除；升级时只注销当前设备的旧推送，不影响其他设备。
这一版没有新增可靠的 iOS 锁屏/后台推送方案。应先检查前台收发、回到前台后补同步和旧通知入口是否清理。

## 本次弹窗修复以后如何验收

等包含本次源码的新包准备好后，覆盖安装并进入聊天列表：

- 标题显示版本和构建号，说明是 `iszkq/fluffychat` 定制版。
- 只有“更新记录”和“关闭”，没有支持按钮或捐助文案。
- 更新记录打开本仓库 Releases；关于页面能再次打开该页面。
- 关闭后再次启动不重复提示；新构建会提示；首次全新安装不提示“已更新”。
